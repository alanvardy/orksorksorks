## Q1: How does `tod` structure its clap-based CLI entrypoint and subcommands?

### Findings
- **Single binary crate, no lib.rs.** All modules declared in `tod/src/main.rs:21-45` (`mod commands; mod config; …`); crate root is `#[tokio::main] async fn main` (`main.rs:57-76`). `Cargo.toml` has `[package]`/`[dependencies]`/`[dev-dependencies]`/`[build-dependencies]` only — **no `[workspace]` section** (`tod/Cargo.toml:1-62`), so `crates/tod-e2e` is a standalone dev crate (own `Cargo.lock`, built via `--manifest-path`, `crates/tod-e2e/tests/e2e_todoist.rs:54-89`).
- **`Cli` + `Commands` live in `src/commands/mod.rs`, not main.rs.** `Cli` (`src/commands/mod.rs:47-73`): `#[derive(Parser, Clone)]`, `#[command(name = NAME, author = AUTHOR, version = LONG_VERSION, about = ABOUT, long_about = None)]`, `#[command(arg_required_else_help(true))]`. Fields: `verbose: bool` (`#[arg(short, long, default_value_t = false)]`), `config: Option<PathBuf>` (`#[arg(short, long)]`), `timeout: Option<u64>`, `json: bool` (**`#[arg(short = 'j', long, global = true, default_value_t = false)]`** — the only global flag), `command: Commands` (`#[command(subcommand)]`).
- **Metadata comes from `env!` constants**, not literals: `NAME = env!("CARGO_PKG_NAME")`, `AUTHOR = env!("CARGO_PKG_AUTHORS")`, `ABOUT = env!("CARGO_PKG_DESCRIPTION")`; `LONG_VERSION` concats `CARGO_PKG_VERSION` + `BUILD_TARGET` + `BUILD_PROFILE` (mod.rs:32-42; BUILD_* emitted by root `build.rs:11-17` from `env::var("TARGET"/"PROFILE")` + chrono timestamp).
- **`Commands` enum** (`mod.rs:75-124`): `#[derive(Subcommand, Debug, Clone)]`, 10 newtype-tuple variants, each `#[command(subcommand)]` + **`#[clap(alias = "x")]` single-char mnemonic** (`p/n/b/t/l/r/c/a/s/e` for Project/Section/Label/Task/List/Reminder/Config/Auth/Shell/Test). Doc comment on each variant starts with `/// (p) Commands that change projects` — mnemonic-first help text. **No `visible_alias` anywhere; no `#[command(flatten)]` anywhere.**
- **Per-group modules, fully self-contained files** under `src/commands/`: each file defines its `#[derive(Subcommand, Debug, Clone)]` group enum, `#[derive(Parser, Debug, Clone)]` args structs, and handlers in the same file. Inventory: `auth_commands.rs` (Login/Token/View), `config_commands.rs` (CheckVersion with `#[clap(short='f',long)] force`, `#[clap(long, hide=true)] repo`), `label_commands.rs`, `list_commands.rs` (View/Process/Timebox/Prioritize/Remind/Label/Schedule/Deadline/Import), `project_commands.rs`, `reminder_commands.rs`, `section_commands.rs`, `shell_commands.rs`, `task_commands.rs` (QuickAdd/Create/Edit/…), `test_commands.rs`. Group enums also use `alias =` on subcommand variants (e.g. `task_commands.rs:18-40`).
- **No shared/grouped-args structs**: fields like `project`/`filter`/`sort` are **duplicated across structs** (e.g. `list_commands.rs:51-226`); shared types are `ValueEnum`s — `SortOrder` (`src/tasks/mod.rs:214-231`) and `Shell` (`src/shell.rs:7`) — consumed positionally (`shell_commands.rs:18-22` `shell: Shell` non-Option).
- **Help-text convention**: field doc-comment sits **below the `#[arg(...)]` attribute** (mod.rs:55-57); struct doc-comment above the struct is the subcommand about-text.
- **Dispatch chain**: `main.rs:59` `Cli::parse()` (clap derive, no custom parser) → `run_command` (`main.rs:126-136`) → `commands::select_command` (`mod.rs:141-158`) which is a `match &cli.command` with one arm per group, each arm calling a private per-group dispatcher in mod.rs (e.g. `project_command` `:237`-ish region) that does a **second `match` on the group enum** into module handlers → handler returns `Result<String, Error>`. Most handlers first `fetch_config(cli, tx)` (`mod.rs:~499-510`) which loads config, applies CLI context, and ensures auth.
- **Exit-code flow**: handlers return `Result<String, Error>`; wrapped in `CommandResult { result, bell_success, bell_failure, json }` (`main.rs:50-55`) by `build_command_result` (bell flags from `config.bell_on_success/on_failure`); `output_result` (`main.rs:78-84`) → `output_text` (success→stdout `println!`+bell, error→stderr `eprintln!("\n\n{e}")`+bell, `main.rs:109-124`)/`output_json` (`{"data": …}` / `{"error": {message, source}}`, `main.rs:86-107`); u8 exit code → `ExitCode::from` (`main.rs:75`). Async-process errors arrive on an `unbounded_channel` drained in `main` (`main.rs:62-73`; `"shell command"` source forces exit 1). Clap parse/help/version exits handled inside clap before `main` body.

## Q3: What error-handling and terminal-output patterns do the author's Rust projects use?

### Findings
- **`tod` error type is hand-rolled**, not thiserror/anyhow (neither appears in tod/api/vardy `Cargo.toml`s; thiserror only transitive in lockfiles; anyhow absent from tod's lockfile). `src/errors.rs:24-27`: `#[derive(Debug, Clone, PartialEq, Eq, Serialize)] pub struct Error { pub message: String, pub source: String }`. Doc (`:11-22`) defines the convention: `source` is a **lowercase crate/module tag string** (`"io"`, `"serde_json"`, `"reqwest"`, `"chrono_tz"`, `"oneshot"`…), and **`Display` owns coloring** — callers must not pre-apply color.
- **`Display`** (`errors.rs:29-39`): `"Error from {yellow source}:\n{red message}"` via `format::yellow_string`/`format::red_string`. **`impl std::error::Error for Error {}` is empty** (`:179`) — no source() override, no typed chain.
- **14 `From<T>` impls**, all flattening to (source tag, formatted message): io→"io" (`:41-48`), regex (`:50-57`), RecvError→"oneshot" fixed msg (`:59-66`), TryFromIntError→"int_convert" (`:68-75`), JoinError→"tokio" (`:77-84`), chrono LocalResult→"chrono_local" w/ per-variant messages (`:86-104`), mpsc SendError→"tokio mpsc" (`:106-114`), chrono_tz (`:116-123`), ParseIntError→"int_parse" (`:125-132`), chrono→"chrono" (`:134-141`), GetHomeError→"homedir" (`:143-150`), serde_json (`:152-159`), reqwest (`:161-168`), inquire (`:170-177`). Constructor `Error::new(source: &str, message: &str)` (`:181-190`) is the primary path (doc: borrow `&format!(...)` results). No macros.
- **Success output convention**: the `✓` character is the universal success marker — via `format::green_string("✓")` (`src/config/file.rs:54`, `config/projects.rs:25`, `task_commands.rs:158,280`, `auth_commands.rs:97-98` with message, `projects.rs:481`) or bare `Ok("✓".into())` (16 sites in `src/todoist/mod.rs`, `src/lists.rs:318,352`). **No ✗/✘/☐/☑ anywhere** in src — failure is conveyed only by the red error text + exit 1.
- **Color module** = `src/format.rs`: wraps the **`colored` crate** (`colored = "3.1.1"`, Cargo.toml:26); `apply_color` (`format.rs:8-13`) **strips ANSI under `cfg!(test)`**; helpers `green_string:18`, `red_string:23`, `cyan_string:28`, `purple_string:33`, `blue_string:38`, `yellow_string:43`, `debug_string:48`, `normal_string:53`; OSC8 hyperlink helpers `format_osc8_link:67`, `create_links:72`. Priority colors: blue=Low/yellow=Medium/red=High (`src/tasks/format.rs:6-13`), `HIGH (P1)` red (`tasks/priority.rs:22`).
- **Propagation to top**: `main.rs:50-55` CommandResult → `run_command` chokepoint (`main.rs:126-136` `unwrap_or_else` → Err with bells true) → `output_text`/`output_json`; JSON error shape = `{"error": {"message": e.message, "source": e.source}}` (only serialization of Error, enabled by `Serialize` derive, `main.rs:99-106`). HTTP 401/403 → `Error::new("reqwest", "Unauthorized or Forbidden…\nRun 'tod auth login'…")` (`src/todoist/request.rs:171-174`).
- **api/vardy differ**: `main() -> Result<(), Box<dyn std::error::Error>>` (`api/src/main.rs:21`, `vardy/src/main.rs:15`) + tracing/Sentry; hand-rolled `AppError`/`WebError` enums with `IntoResponse`→StatusCode+JSON ErrorBody (`api/src/app/error.rs:45-62,84+`; `vardy/src/app/error.rs:11-16,60+`). No thiserror/anyhow in either.

## Q4: How do the author's Rust projects create and write files?

### Findings
- **Canonical helper `Config::touch_file`** (`tod/src/config/file.rs:24-31`): `if let Some(parent) = path.parent() { fs::create_dir_all(parent).await?; } fs::File::create(&path).await?;` — parent creation only when a parent exists, then create-or-truncate (tokio::fs).
- **`Config::save`** (`file.rs:33-56`): re-loads existing config to preserve `verbose` (`match Config::load…`), `serde_json::to_string_pretty(&json!(config))`, opens with `OpenOptions::new().write(true).read(true).truncate(true)` (no `create_new`), `write_all` → **`flush()` → `sync_all()`** → returns `Ok(format::green_string("✓"))` (the ✓ doubles as both output and success signal). Errors bubble via `?` into `Error` via `From<std::io::Error>` ("io" tag, `errors.rs:41-48`); `serde_json` parses map to `config_load_error` → `Error::new("serde_json", …)` (`file.rs:81-89`).
- **Production call pattern**: config mutations end in `config.save().await?` (`src/projects.rs:156,162,169,195,212,233,266,305,336`; `config/mod.rs:398,756`; `config/timezone.rs:30-33`; `oauth.rs:51`); create-in-place on `ErrorKind::NotFound` = `Config::new` + `touch_file()` + `save()` (`commands/auth_commands.rs:45-55`). Background save failures are caught, not propagated: `src/tasks/mod.rs:548` `if let Err(e) = reloaded_config.save().await { eprintln!(…) }`. Reset/delete uses `fs::try_exists` then manual `Error::new("config_reset", …)` wrap (`file.rs:141-175`).
- **Note**: a second write path (config-check repair, `config_commands.rs:317-323`) writes via OpenOptions + `write_all` **without** flush/sync_all.
- **vardy** is the only other FS-touching project: SQLite `create_if_missing(true)` + manual `std::fs::create_dir_all(parent).expect(...)` since sqlx doesn't create parents (`vardy/src/app/db.rs:12-25`). api writes no local files (Postgres, `grep std::fs` in src → no matches). Both write logs to stderr with BrokenPipe-tolerant `StderrWriter` (`api/src/app/log.rs`, `vardy/src/app/log.rs:20-38`).
- **`toml` crate: not used directly in any Rust project under `~/dev/`.** Zero hits in all Cargo.tomls. Only transitive lockfile entries (0.8.23) via **`rust_arkitect = "0.3.7"`** in api (`api/Cargo.toml:48`) and vardy (`vardy/Cargo.toml:26`) — never called from project source (`toml::from_str`/`to_string`/`Value` unused). `tod/Cargo.lock`: zero `name = "toml"`.
- **Serialization = JSON only** (serde_json): config `to_string_pretty`/`from_str` (`file.rs:43,66`), `json!` macro (`file.rs:7`); no YAML anywhere. Beyond JSON: minijinja HTML templates, sqlx migrations, and toml_edit/toml consumed internally by arkitect only.

## Cross-Cutting Observations
- **Convention spine**: clap-derive CLI + hand-rolled `(message, source)` Error + tokio::fs helpers + serde_json config + `✓`-success output + nextest + `-D warnings` clippy + fmt --check + TODO/FIXME rg gate + codecov, repeated across CLI AND web projects.
- **The `✓` success string is a data-return convention**: `save()` returns `Ok(format::green_string("✓"))` so the printed success marker is just the handler's return value — no separate print layer.
- **Errors are shape-enforced**: `Serialize` on `Error` + a single JSON error envelope (`{"error":{message,source}}`) means every failure mode is representable in JSON mode; `Display` centralizes color so callers stay plain.
- **Dispatch is a two-level match** (`select_command` on `Commands` → per-group dispatcher on `*Commands`), with per-group dispatchers co-located in `commands/mod.rs` and handlers in per-group modules.
- **cfg!(test) color stripping** (`format.rs:8-13`) is what lets unit tests assert colored strings without ANSI — a deliberate testability seam, plus `main.rs:4` `#![warn(missing_docs)]` driving doc comments.
- **Workspaces/flatten/copy-paste avoidance are not part of the style**: no workspaces, no flatten, shared args duplicated, no macro-generated errors.
